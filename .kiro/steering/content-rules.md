# 콘텐츠 작성 규칙 (Developing on AWS 정리 자료)

이 프로젝트는 AWS 공식 교재(강사용 덱)를 마크다운 학습 자료로 변환합니다.
수강생이 공식 교재를 손에 들고 이 자료를 함께 봅니다. 따라서 **틀린 내용을 쓰는 것이
빠뜨리는 것보다 훨씬 나쁩니다.** 아래 규칙은 협상 대상이 아닙니다.

## 1. 2단계 분리 원칙

요약과 최신화를 **절대 같은 작업에서 섞지 않습니다.** 섞으면 모델이 오래된 강사 노트를
근거로 현재 사실을 추측합니다.

| 단계 | 입력 | 출력 | 규칙 |
|---|---|---|---|
| 1단계 요약 | `pipeline/extracted/MNN.json` (또는 `.txt`) | `pipeline/drafts/MNN.stage1.md` | 원문(슬라이드 본문 + 강사 노트)에 **없는 사실은 한 줄도 추가하지 않는다**. 검증이 필요한 지점은 `<!-- VERIFY:id -->` 마커로 남긴다 |
| 2단계 최신화 | 1단계 산출물 + AWS 공식 문서 | `webapp/public/content/MNN-*.md` | **실제로 조회한 문서만** 근거로 삼는다. 조회하지 못한 항목은 추가하지 않고 `8.5 검증하지 못한 항목`에 적는다 |
| 3단계 번역 | 한국어 최종본 | `webapp/public/content/en/MNN-*.md` | 사실을 **추가하거나 바꾸지 않는다**. 인용 URL은 동일하게 유지한다. 장 구조와 표를 1:1로 맞춘다 |

두 단계를 별도 커밋으로 남기면 diff가 곧 "교재 이후 무엇이 바뀌었나"의 기록이 됩니다.

## 1-1. 로케일 구성

| 로케일 | 콘텐츠 경로 | 비고 |
|---|---|---|
| `ko` | `webapp/public/content/MNN-*.md` | 기본. 하위 디렉터리 없음 |
| `en` | `webapp/public/content/en/MNN-*.md` | 파일 이름은 한국어본과 **동일** |

- 파일 이름은 로케일과 무관하게 하나입니다. `navigationTree.js`의 `contentFile`이 그 이름입니다.
- UI 문자열(버튼, 라벨, 안내 문구)은 콘텐츠가 아니라 `webapp/src/i18n/strings.js`에 둡니다.
- 모듈 제목은 `navigationTree.js`의 `title: { ko, en }`에 둡니다.
- 영어 문서는 헤딩이 영어이므로 **앵커 슬러그도 영어**가 됩니다. 목차와 본문 참조 링크를
  한국어본에서 그대로 복사하면 전부 깨집니다. 게이트가 잡아주지만 처음부터 맞추세요.

## 2. 사실 확인 규칙

- 서비스 이름, 한도, 수치, API 이름, 기본값, 지원 종료 일정, 런타임 버전처럼 **검증 가능한
  사실**에는 반드시 근거를 붙입니다.
- 근거는 **인터넷에서 실제로 조회한 AWS 공식 문서 페이지**만 사용합니다.
  기억이나 추론으로 쓰지 않습니다. 조회하지 않은 페이지를 인용해서도 안 됩니다.
- 교재 내용이 현재와 다르면 `pipeline/facts/deprecations/MNN.yaml`에 등재합니다.
  상태는 `ended`(지원 종료) / `discouraged`(비권장) / `changed`(동작·기본값 변경) /
  `incorrect`(교재 기술 오류) 중 하나입니다.
- **문서로 확인하지 못한 것은 확인하지 못했다고 씁니다.** 단정하지 않습니다.

### 2-1. 어떤 도메인을 공식 문서로 보는가

판단 기준은 **AWS 가 직접 운영하고 저작권을 보유한 도메인**입니다.
`docs.aws.amazon.com` 밖에도 공식 문서가 있습니다. 예를 들어 Boto3 리소스 인터페이스의
지원 상태는 `boto3.amazonaws.com` 에만 있고, 그 사이트는 AWS 가 운영하며
저작권 표기도 Amazon Web Services, Inc. 입니다.

허용 도메인 목록은 코드가 아니라 데이터로 관리합니다:
**`pipeline/facts/source-domains.yaml`**

| 계층 | 내용 | 조회 도구 |
|---|---|---|
| `tier1` | `docs.aws.amazon.com`. **1순위.** 가능하면 항상 여기서 찾습니다 | AWS Documentation MCP (`search_documentation` / `read_documentation` / `read_sections` / `search_table`) |
| `tier2` | AWS 가 운영하는 그 외 공식 도메인 (`aws.amazon.com` 블로그·요금·공지, `boto3.amazonaws.com`, `botocore.amazonaws.com`, `awscli.amazonaws.com`, `sdk.amazonaws.com`, `docs.amazonaws.cn`) | MCP 로는 가져올 수 없으므로 `web_fetch` |
| `informational` | AWS 소유가 아니지만 본문에서 참고용으로 링크해도 되는 곳 (`publicsuffix.org` 등) | `web_fetch` |

- 같은 사실이 tier1 과 tier2 에 모두 있으면 **tier1 을 인용합니다.**
- `informational` 도메인은 **출처 인용에 쓸 수 없습니다.** 사실의 근거는 항상 AWS 공식
  도메인이어야 하고, 참고 링크는 본문 안에서만 씁니다.
- 목록에 없는 도메인이 필요하면 먼저 `source-domains.yaml` 에 근거(`note`)와 함께
  등재합니다. 게이트가 목록을 기준으로 검사하므로 코드를 고칠 필요는 없습니다.
- 커뮤니티 콘텐츠(`repost.aws`, Stack Overflow, 블로그 플랫폼 등)는 AWS 가 운영하더라도
  답변 작성자가 AWS 가 아닐 수 있으므로 근거로 쓰지 않습니다.

### 2-2. 근거 기록 형식

조회한 근거는 `pipeline/facts/citations/MNN.json`에 남깁니다. `verified_on` 날짜를 갱신합니다.

근거와 폐기 항목은 **모듈별 파일로 나눕니다.** 한 파일에 모으면 여러 모듈을 동시에
작업할 때 서로 덮어씁니다. `source-domains.yaml`만 공용이고 읽기 전용으로 씁니다.

| 필드 | 내용 |
|---|---|
| `id` | 본문에서 이 근거를 가리키는 식별자 |
| `claim` | 문서에서 확인한 내용 |
| `url` | 조회한 페이지 |
| `fetched_with` | 어떻게 조회했는지. `mcp` / `web_fetch` / `link_check` 중 하나 |
| `section` | 페이지 내 섹션 |
| `corrects_courseware` | 교재와 다른 점 (해당하는 경우) |

`fetched_with` 의 의미:

- `mcp` — AWS Documentation MCP 로 페이지를 읽었다
- `web_fetch` — `web_fetch` 로 페이지를 읽었다 (MCP 가 다루지 않는 공식 도메인)
- `link_check` — **URL 이 살아 있는지만 확인했고 내용은 읽지 않았다.**
  "이 URL 이 유효하다" 자체가 주장인 경우에만 쓸 수 있습니다.
  페이지 내용에 근거한 주장에는 쓸 수 없습니다.

이 필드를 남기는 이유는 재검증입니다. 나중에 사실이 바뀌었는지 확인할 때,
어떤 도구로 무엇을 봤는지 알아야 같은 경로로 다시 확인할 수 있습니다.

## 3. 교재를 조용히 고치지 않기

수강생은 교재와 대조합니다. "책에는 Cloud9이 있는데요?"라는 질문에 답할 수 있어야 합니다.

모든 모듈 문서에 **`N. 교재 대비 변경 사항`** 장을 둡니다. 구성은 다음과 같습니다.

| 절 | 내용 |
|---|---|
| N.1 | 교재 기술이 사실과 다른 항목 (교재 기재 / 확인된 내용 / 근거) |
| N.2 | 동작·기본값이 변경된 항목 |
| N.3 | 비권장·지원 종료된 항목 (상태 / 대체 / 근거) |
| N.4 | 교재 이후 추가된 항목 |
| N.5 | 검증하지 못한 항목 |

## 4. 문서 형식

### 골격

```
# 모듈 N: <교재 그대로의 모듈명>

## Developing on AWS (한국어)

---

## 목차
1. [...](#앵커) …

> **표기 설명**
>
> - 🆕 원본 강사용 덱에 없는 내용. AWS 공식 문서로 확인한 항목입니다.
> - 🔄 원본 강사용 덱의 내용이 현재와 달라 교정한 항목입니다. …
> - 검증일: YYYY년 M월 D일. …

---

<본문 장>
…
## N. 교재 대비 변경 사항   ← 마지막 장
```

### 규칙

- 모듈 번호는 **교재와 1:1로 유지**합니다. 수강생이 대조하기 때문입니다.
- 🆕 / 🔄 표기를 쓴 H2 섹션에는 **출처 인용이 반드시 있어야** 합니다(게이트가 검사).
- 출처는 인용문으로 답니다. 형식이 정해져 있고 게이트가 이 형식을 찾습니다.
  - 한국어: `> — 출처: [문서 제목](url)`
  - 영어: `> — Source: [Document title](url)`
  - 줄바꿈(`—`), 키워드, 콜론, 그리고 **같은 줄의 링크**까지 있어야 인식됩니다.
- 표를 적극적으로 씁니다. 비교·목록형 정보는 산문보다 표가 강의에 유용합니다.
- 코드 주석은 **한글**로 씁니다. 변수·함수명은 영어를 유지합니다.
- 코드 블록에는 **반드시 언어 태그**를 붙입니다(게이트가 검사).
  하이라이팅되는 언어는 `webapp/src/components/CodeBlockWrapper.jsx`의 `LANGUAGES`에
  등록된 것뿐입니다. 새 언어를 쓰려면 거기에 먼저 추가합니다.
- 문서 상단 **표기 설명** 블록은 인용문 안의 목록으로 씁니다. `> - 항목` 형태입니다.
  인용문에서 줄바꿈만으로는 한 문단으로 이어져 붙어 나옵니다(GFM 은 기본적으로
  줄바꿈을 `<br>` 로 바꾸지 않습니다). 목록으로 쓰면 항목이 확실히 나뉩니다.
  제목은 `표기 설명`(영문 `Notation`)으로 통일합니다.
- **지식 확인 문제(퀴즈)는 두지 않습니다.** 이 사이트는 교재 요약과 최신화 대조가 목적이고,
  문제 풀이는 교재와 Skill Builder 가 담당합니다. `교재 대비 변경 사항`이 **마지막 장**입니다.
  기존 문서에 있던 `지식 확인 및 핵심 정리` 장은 2026년 9월 2일에 전 모듈에서 제거했습니다.

### 앵커 슬러그

목차와 본문 참조 링크의 앵커는 다음 규칙으로 생성됩니다.

1. 소문자화 → 2. 유니코드 문자·숫자·공백·하이픈만 남김 → 3. 공백을 하이픈으로 →
4. **앞뒤 하이픈 제거**

4번을 자주 틀립니다. 헤딩이 `### 3.7 기본 암호화 🔄`처럼 이모지로 끝나면
앵커는 `#37-기본-암호화`이고 **`#37-기본-암호화-`가 아닙니다.**

구현이 두 곳에 있고 **동작이 일치해야** 합니다. 한쪽만 바꾸면 링크가 조용히 깨집니다.

- `webapp/src/components/MarkdownRenderer.jsx` → `slugify()`
- `pipeline/validate.py` → `slugify()`

페이지 목차(Cloudscape Anchor navigation)도 같은 앵커를 씁니다.
`webapp/src/lib/markdownOutline.js` 는 `slugify()` 를 가져다 쓰므로 슬러그 규칙 자체는
한 곳입니다. 다만 슬러그에 넣을 **텍스트를 뽑는 방식**이 갈립니다.

- 본문 헤딩: `MarkdownRenderer.jsx` 의 `extractText()` — 파싱된 결과에서 텍스트를 모읍니다
- 목차 항목: `markdownOutline.js` 의 `displayText()` — 원본 마크다운에서 표기를 걷어냅니다

두 결과가 달라지면 목차 링크만 조용히 깨집니다. 렌더 검사의 `페이지 목차` 항목이 이걸
잡으므로, 헤딩에 새로운 인라인 표기(예: 링크)를 쓰기 시작하면 `displayText()` 를 함께
손봐야 합니다.

## 5. 게시 전 게이트

`webapp/public/content/`에 파일을 넣거나 고친 뒤에는 **반드시** 실행합니다.

```bash
python3 pipeline/validate.py            # 모든 로케일 전체 (ko + en/)
python3 pipeline/validate.py M05-Storage1_Summary   # 같은 이름 파일을 로케일별로 모두
python3 pipeline/validate.py --skip-links   # 오프라인
```

검사 항목:

| # | 검사 | 위반 시 |
|---|---|---|
| 1 | `<!-- VERIFY:... -->` 마커 잔존 (2단계 미완료 상태로 게시 차단) | 실패 |
| 2 | 모든 인라인 앵커가 실제 헤딩과 일치하는지 | 실패 |
| 3 | 본문 링크가 HTTP 200으로 응답하는지 | 실패 |
| 4 | 코드 블록 언어 태그 누락 / 닫히지 않은 펜스 | 실패 |
| 5 | 🆕 / 🔄 섹션의 출처 누락 | 실패 |
| 6 | **출처 인용 도메인이 `source-domains.yaml` 의 tier1·tier2 인지** | 실패 |
| 7 | **`facts/citations/*.json` 의 모든 항목에 `fetched_with` 가 있고 url 도메인이 허용 목록인지** | 실패 |
| 8 | 그 밖의 본문 링크가 허용 목록 밖 도메인인지 | 경고 |
| 9 | `facts/deprecations/*.yaml`의 `ended` 항목이 본문에 등장하는지 | 경고 |

근거 검사(7번)는 콘텐츠 파일마다 돌지 않고 한 번만 실행됩니다.

게이트를 통과하지 못한 콘텐츠는 게시하지 않습니다.

## 6. 파이프라인 명령

```bash
python3 pipeline/extract.py            # PPT 15덱 전부 -> extracted/*.json
python3 pipeline/extract.py m5         # m5 로 시작하는 덱만 (index.json 안 건드림)
python3 pipeline/dump.py M05           # JSON -> 사람이 읽는 평문 대장 .txt
python3 pipeline/validate.py           # 게이트
python3 pipeline/fix_yaml_quotes.py    # deprecations/*.yaml 인용부호 보강
```

`fix_yaml_quotes.py` 는 `courseware_location: 슬라이드 16 "객체 업로드: PUT" 강사 노트`
처럼 값에 `: ` 가 들어가 파서가 죽는 줄을 찾아 인용부호를 씌웁니다.
블록 스칼라(`>-`, `|`) 본문은 들여쓰기로 추적해서 건드리지 않습니다.

**게이트는 모든 모듈의 `deprecations/*.yaml` 을 한 번에 읽습니다.** 그래서 한 모듈의
YAML 문법 오류 하나가 전체 게이트를 파싱 단계에서 죽입니다. 다른 모듈이 멀쩡한데 게이트가
통째로 죽으면 이걸 먼저 의심하세요.

앱:

```bash
cd webapp && npm install
npm run dev            # 개발 서버
npm run build          # dist/ 생성 + 토큰 검사
npm run validate       # 콘텐츠 게이트
npm run check:render   # 실제 렌더 검증 (개발 서버가 떠 있어야 함, 8장 참조)
```

## 7. 새 모듈을 추가할 때

1. `python3 pipeline/dump.py MNN` 으로 원문 대장을 만들고 **전부 정독**합니다.
2. 1단계 초안을 `pipeline/drafts/MNN.stage1.md`에 씁니다. VERIFY 마커를 남깁니다.
3. VERIFY 항목을 AWS 공식 문서로 하나씩 확인하고 `facts/citations/MNN.json`·
   `facts/deprecations/MNN.yaml`을 씁니다. 각 근거에 `fetched_with` 를 반드시 넣습니다(2-2 참조).
   `docs.aws.amazon.com` 밖의 공식 도메인이 필요하면 `source-domains.yaml` 을 먼저
   확인하고, 없으면 근거와 함께 등재합니다(2-1 참조).
4. `webapp/public/content/MNN-*.md`에 한국어 최종본을 씁니다.
5. `webapp/public/content/en/MNN-*.md`에 영어본을 씁니다. 앵커는 영어 슬러그로 다시 맞춥니다.
6. `webapp/src/data/navigationTree.js`의 해당 항목에 `contentFile`과 `tags`를 채우고
   `title`에 `ko`·`en`을 모두 넣습니다.
   (`contentFile`이 없으면 사이드 내비에 "(준비 중)"으로 표시됩니다.)
7. `python3 pipeline/validate.py` 를 통과시킵니다. 로케일 두 개가 모두 통과해야 합니다.
8. `cd webapp && npm run build` 로 빌드가 깨지지 않는지 확인합니다.
9. `npm run check:render` 로 실제 렌더를 확인합니다(8장 참조). 검사 대상은
   `navigationTree.js` 에서 자동으로 잡히므로 6번을 하면 함께 들어갑니다.

`navigationTree.js` 의 `id` 는 **`contentFile` 에서 `.md` 를 뺀 문자열과 같게** 유지합니다.
콘텐츠가 아직 없는 모듈도 확정된 파일 이름을 미리 `id` 로 씁니다. 그러면 콘텐츠를 붙일 때
`contentFile` 한 줄만 추가하면 되고, id 와 파일 이름이 어긋나는 일이 없습니다.

## 8. 렌더 검증 방법

게이트는 마크다운 텍스트만 봅니다. 실제로 화면에 제대로 그려지는지는 별도로 확인합니다.

```bash
cd webapp && npm run dev          # 먼저 개발 서버를 띄웁니다
npm run check:render                          # 기본 http://localhost:5173
npm run check:render -- http://localhost:5174 # 포트가 다르면 인자로 넘깁니다
```

`webapp/scripts/render-check.mjs` 가 Chrome DevTools Protocol 로 브라우저를 조작합니다.
모듈마다 사이드바 링크를 **실제로 클릭**해서 렌더한 뒤 다음을 확인합니다.

모듈별 검사:

| 검사 | 실패 조건 |
|---|---|
| 콘텐츠 로드 | 오류 알림이 떠 있음 |
| 헤딩 | h1 없음, h2 3개 미만 |
| 표 | 5개 미만 |
| 코드 블록 | 0개, 또는 복사 버튼 수와 불일치, 또는 구문 하이라이팅 없음 |
| 출처 | 5개 미만 |
| VERIFY 마커 | 하나라도 남아 있음 |
| 인라인 앵커 | 대상 헤딩이 없는 링크가 하나라도 있음 |
| 페이지 목차 | 목차가 없음, 항목 3개 미만, 대상 헤딩이 없는 항목이 있음, 중첩 3단계 초과, 활성 항목이 둘 이상 |

페이지 목차는 **내비게이션 패널의 모듈 트리 아래**에 둡니다(Cloudscape Anchor navigation).
AWS 실습 화면이 왼쪽 패널에 `실습 정보` 와 `실습 콘텐츠` 를 쌓는 것과 같은 구성입니다.
본문 옆 컬럼으로 두면 안 됩니다. Cloudscape Grid 는 자기 컨테이너 너비로 브레이크포인트를
정하는데 사이드 내비게이션이 280px 을 차지하므로, 창 너비를 기준으로 배치를 정하면 두
판단이 어긋나 특정 폭 구간에서 목차가 본문 전체 아래로 밀립니다(실제로 겪었습니다).

목차에는 **h2 만** 담습니다. h3 까지 넣으면 모듈당 40~90 항목이 모듈 트리 아래에 붙습니다.
모듈 트리에는 높이 상한을 두어 목차가 늘 화면에 남게 합니다.

앱 동작 검사:

| 검사 | 실패 조건 |
|---|---|
| 모드 전환 | `awsui-dark-mode` 미적용, 본문색·코드배경이 모드에 따라 안 바뀜, 코드배경이 `#f8f8f8`/`#282c34` 아님 |
| 로케일 전환 | 제목이 안 바뀜, 전환된 로케일에서 앵커 깨짐 |
| 읽음 표시 | 사이드바 항목에 "읽음"/"Read" 가 보임 |
| 딥링크 | `#<모듈 id>` 로 접속했는데 그 모듈이 안 열림, 또는 해시가 유지되지 않음 |
| 열 수 없는 해시 | 준비 중 모듈 해시가 주소에 그대로 남음 (리로드 경로·hashchange 경로 각각 확인) |
| 뒤로 가기 | 이전 모듈로 돌아가지 않음 |
| 본문 앵커 | 목차·상호 참조 클릭이 모듈 해시를 덮어씀 |
| 페이지 목차 | 스크롤해도 활성 항목이 생기지 않음(스크롤 스파이 미동작), 활성 항목이 둘 이상, 목차 링크가 모듈 해시를 덮어씀 |

검사 대상은 스크립트가 `navigationTree.js` 를 직접 불러와서 정합니다. `contentFile` 이 있는
모듈은 자동으로 검사에 들어가므로 **따로 목록을 갱신할 필요가 없습니다.** 열 수 없는 해시
검사에 쓰는 "준비 중 모듈"도 트리에서 골라 씁니다. 이렇게 하지 않으면 특정 모듈 이름을
박아 둔 검사가 그 모듈이 게시되는 순간 거짓 실패를 냅니다(실제로 M09 에서 겪었습니다).

### 딥링크 규칙

주소의 해시는 **모듈 딥링크 전용**입니다. `http://호스트/#M06-Storage2_Summary` 형태입니다.

- 목차·본문 상호 참조는 해시를 건드리지 않고 `scrollIntoView` 로 직접 스크롤합니다.
  해시를 덮어쓰면 그 주소를 새로고침·공유했을 때 어느 모듈이었는지 알 수 없게 됩니다.
- 열 수 없는 해시(준비 중 모듈, 옛 본문 앵커)는 첫 모듈로 넘어가고 **주소를 정정**합니다.
  주소가 화면과 다른 모듈을 가리킨 채 남으면 안 됩니다.
- 정정 경로가 두 개입니다. 경로가 같고 해시만 다른 이동은 브라우저가 페이지를 다시
  로드하지 않으므로(same-document navigation) 마운트 효과가 돌지 않습니다.
  그래서 마운트 시 정정과 `hashchange` 시 정정을 **둘 다** 두어야 하고, 테스트도 둘 다 합니다.
- 모듈 이동은 `pushState` 로 남겨 뒤로 가기가 동작하게 합니다. `pushState` 는
  `hashchange` 를 발생시키지 않으므로 동기화 리스너와 겹쳐 돌지 않습니다.

### 왜 `--dump-dom` 만으로는 부족한가

`--dump-dom` 은 페이지 로드 직후의 DOM 을 한 번 찍는 것뿐이어서 이 앱에는 맞지 않습니다.

- **앱이 URL 해시를 읽지 않습니다.** `activeItemId` 는 `firstAvailableId()` 로 초기화되므로
  `http://localhost:5173/#M06-Storage2_Summary` 를 덤프해도 **항상 첫 모듈**이 나옵니다.
  모듈별 확인에는 클릭이 필요합니다.
- **`--force-dark-mode` 는 쓰면 안 됩니다.** 브라우저가 픽셀을 강제로 반전시켜서
  앱이 실제로 다크 토큰을 적용했는지 판별할 수 없게 됩니다. 다크 모드는 앱의 토글을
  클릭하고 `getComputedStyle` 로 확인해야 합니다.
- **프로파일을 재사용하면 안 됩니다.** 다크 모드·로케일이 `localStorage` 에 남아 있어서
  다음 실행의 시작 상태가 달라집니다. 스크립트는 매 실행 새 `--user-data-dir` 을 만들고
  끝나면 지웁니다. 판정도 시작 방향을 가정하지 않습니다.

### 셀렉터 함정

수를 셀 때 아래를 틀리면 통과·실패가 뒤바뀝니다.

| 대상 | 올바른 셀렉터 | 틀리는 이유 |
|---|---|---|
| 코드 블록 | `table[class*="code-table"]` | Cloudscape `CodeView` 는 **`<pre>` 를 쓰지 않습니다.** 코드 한 줄이 `<td class="awsui_code-line">` 이고 블록 전체가 `<table>` 입니다. `pre` 로 세면 0 이 나옵니다 |
| 본문 표 | `table` 수 − `code-table` 수 | 코드 블록이 `<table>` 이라 그냥 세면 부풀려집니다 |
| 코드 배경색 | 투명하지 않은 첫 조상까지 올라가서 읽기 | `code-table` 바로 위 `div` 는 투명합니다. 배경은 `.ace-cloud_editor` / `.ace-cloud_editor_dark` 래퍼에 있습니다 |
| 상단 유틸리티 버튼 | `#top-nav a[aria-label]` 중 `offsetParent !== null` | 유틸리티는 `<button>` 이 아니라 **`<a>`** 이고, 반응형 레이아웃 때문에 숨겨진 사본이 여러 개 존재합니다. `querySelectorAll('button').at(-1)` 로 집으면 엉뚱한 것을 누릅니다 |
| `code-view` 문자열 검색 | 요소 클래스로 찾기 | `--color-background-code-view-...` 라는 **CSS 변수명**이 DOM 에 들어 있어서 문자열 검색은 오탐이 납니다 |

DOM 을 직접 덤프해 검사할 때는 한 줄에 여러 항목이 몰려 있으므로 `grep -c`(줄 수)가 아니라
`grep -o ... | wc -l` 을 씁니다. 또 개발 서버는 CSS 를 인라인으로 주입하므로 CSS 주석의
한글이 검색에 걸릴 수 있습니다.
