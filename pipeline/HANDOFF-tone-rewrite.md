## 1. 사용자가 요청한 것 (원 요구사항)

M02~M14 각 모듈에 공통 적용:

1. **메인 자료 톤** — 교재와 대조하는 보조 자료가 아니라, 이 웹앱만 보고도 필요한 지식을
   공부할 수 있는 메인 자료로 만든다.
2. **교재 비교 문구·내용 삭제** — 본문에서 "교재는 X라고 하지만 Y", "슬라이드가 말하는 것" 같은
   대조 서술을 걷어낸다.
3. **슬라이드 번호 제거** — "슬라이드 9", "(슬라이드 12)" 같은 표기 전부 제거.
4. **마지막 섹션에 차이점·추가점 표** — 각 모듈 마지막 `교재 대비 변경 사항` 섹션은
   **이름을 그대로 유지**하고, 교재와 다른 점 + 웹앱에서 추가된 점을 표로 정리한다.
   어떤 부분이 다른지, 왜 추가했는지 언급한다. (사용자가 "1번안"으로 확정: 섹션 이름 유지)
5. **아키텍처 다이어그램은 ASCII 아트로** 작성.

범위 확정: 사용자가 "모듈 2번부터 4번까지만 선 적용" → 확인 후 "나머지 모듈들도 이어서" 지시.
현재 M02~M10 완료, M11부터 재개.

## 3. 재작성 규칙 (M02~M05에서 확립한 패턴)

### 3.1 본문 톤
- "교재는 X라고 하지만 Y" → **"Y"** (독립 서술). 사실만 남기고 대조 프레임 제거.
- "슬라이드가 말하는 것 / 현재 문서는 다름" 2단 구조 → 하나의 지식 서술로 통합.
- 문장 주어를 **AWS 사실**로. (교재/슬라이드/강사 노트가 주어가 되지 않게)
- 🆕/🔄 이모지 표기와 `> — 출처:` 인용은 **그대로 유지**. 사실·출처·URL·코드는 절대 안 바꿈.
- 헤딩·표 제목의 `(슬라이드 N)`, `(교재 기재)` 제거.
- 코드 주석의 "교재 예제는 v1/v2 혼용..." 류 → "아래는 AWS SDK for Java 2.x 문법입니다" 식으로.

### 3.2 표기 설명(문서 상단) 2줄 교체 (ko)
```
> - 🆕 강의에서 다루지 않은 내용. AWS 공식 문서로 확인해 더한 항목입니다.
> - 🔄 강의 당시와 달라져 교정한 항목입니다. 무엇이 어떻게 달라졌는지는 [N장](#...)에 모아 두었습니다.
```
(en)
```
> - 🆕 Material the class did not cover, added after verifying it against official AWS documentation.
> - 🔄 Material that has changed since the class and has been corrected here. See [Section N](#...) for what changed and how.
```

### 3.3 마지막 장(교재 대비 변경 사항) 재구성
- 이름 유지: `교재 대비 변경 사항` / `Changes from the Courseware`. (M16이 이 이름으로 참조하므로 변경 금지)
- 도입문 교체 (ko):
  ```
  수강생이 공식 교재를 함께 볼 수 있으므로, 이 자료가 교재와 어디서 갈라지는지 한곳에 모았습니다.
  앞 장에서 신규·교정으로 표시한 항목의 근거가 여기 있습니다.
  ```
  (en)
  ```
  Since learners may have the official courseware in front of them, this section gathers in one
  place where this material diverges from it. The evidence behind every item marked new or
  corrected in the sections above is here.
  ```
- 하위 절 구조: **N.1 교재와 다른 점 / N.2 동작·기본값이 변경된 항목 / N.3 비권장·지원 종료된 항목 /
  N.4 이 자료에서 더한 점 / N.5 검증하지 못한 항목**
  - N.1 제목: `교재 기술이 사실과 다른 항목` → **`교재와 다른 점`** (en: `Differences from the Courseware`)
  - N.4 제목: `교재 이후 추가된 항목` → **`이 자료에서 더한 점`** (en: `What This Material Adds`).
    표에 **"왜 더했는가"** 열을 추가 (기존 "요약" 열을 왜 열로 대체하거나 앞에 추가).
  - N.2·N.3·N.5 표의 "교재 기재" 등 열 헤더는 "교재의 서술" / "흔한 오해" 등으로 자연스럽게.
    이 장은 교재와의 차이를 다루는 곳이므로 "교재" 단어 자체는 남아도 됨.

### 3.4 아키텍처 → ASCII (` ```text ` 펜스)
- M02는 3개(전체 아키텍처/요청 흐름/Cognito 인증 흐름), M04는 3개 만들었음.
- 다이어그램 요소만 나열된 표나 "→ ... → ..." 흐름 서술을 ```text 블록으로.

## 4. 두 가지 함정 (반드시 지킬 것)

### 4.1 게이트 규칙 6 — 이모지 "언급"도 걸린다
`pipeline/validate.py`는 H2 섹션 안 **인용문(>) 밖**에 🆕/🔄 이모지가 있으면 그 섹션에
`> — 출처:` 인용문을 요구합니다. 마지막 장 도입문에서 "🆕·🔄로 표시한 항목"처럼 이모지를
**언급만 해도** 걸립니다. → 반드시 "신규·교정으로 표시한" / "marked new or corrected"로 바꿀 것.
(M02에서 이걸로 게이트 실패했었음)

### 4.2 render-check.mjs — 이미 보정 완료
코드블록이 있으면 구문 하이라이팅 span을 무조건 요구하던 문제를, 원본 md의 펜스 언어를 읽어
`text`/`plaintext`/`txt`/`plain` 외 언어가 있는 모듈만 하이라이팅을 요구하도록 고쳤습니다
(`ce2eb3c`에 포함). ASCII 다이어그램(```text)만 있는 문서는 이제 거짓 실패 안 남. **추가 작업 불필요.**

### 진행 방법 (M02~M10에서 확립, M11에 그대로 적용)
1. 본문의 교재/슬라이드/강사 노트 언급 위치를 아래 명령으로 뽑습니다(N = 마지막 장 번호):
   ```bash
   awk '/^## N\./{exit} /슬라이드|강사 노트|교재|지식 확인/{print NR": "$0}' \
     webapp/public/content/M11-Microservices_Summary.md
   ```
   각 줄을 3.1 규칙대로 독립 서술로 고칩니다. 마지막 장은 3.3 규칙대로.
2. en도 동일하게(`webapp/public/content/en/M11-Microservices_Summary.md`,
   `courseware|slide|instructor note` 로 검색).
3. 마지막 장의 `(슬라이드 N)` 표기도 전부 제거합니다(M05~M08처럼). "교재" 단어 자체는
   그 장에 남아도 됩니다.
4. 아키텍처/흐름이 표나 "→" 서술로 되어 있으면 ```text ASCII 블록으로 바꿉니다.
   (M06 4.1, M07 5.1처럼. 후보가 없으면 생략 — M08은 생략했음.)
5. 본문의 "교재의 자체 모순" 류 절은 올바른 사실 서술로 바꾸고(M10에서는 "일부 원본 자료는

- 게이트: `python3 pipeline/validate.py M11-Microservices_Summary`
